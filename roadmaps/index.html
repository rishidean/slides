Part one

What’s changed

Why the roadmap that served you for years stops working.

WHAT’S CHANGED · THE INVERSION

Your specs are no longer read by the people who wrote them

FOR DECADES

Specs written for humans. Machines scraped them as an afterthought.

Prose, decks, tribal knowledge; a person filled every gap.

NOW

The agent is the primary reader. The human view is generated on top.

A wall of well-meaning prose a person would skim politely is noise to a machine.

If a document isn’t legible to the agent, nothing downstream of it is.

slides.rishidean.com/roadmaps6
WHAT’S CHANGED · THE BAR

Four properties, or the agent goes back to guessing

Consolidated

Synthesized once, written down. Never re-derived from scratch every session.

Contextual

In the repo, next to the work. The agent never goes hunting through a connector.

Close-to-code

Structured and machine-native. States and lists, not paragraphs about them.

Current

Regenerated or validated when reality changes, so it can’t drift into fiction.

Every roadmap failure you’ve seen is one of these four, missing.

DEFINITION

The manifest

An agentic roadmap is the manifest of the work: what exists, what’s next, and what’s in flight, in a form an agent can read, execute, and update.

read execute update ← the agent does all three

Not a slide you present quarterly. A file the system runs on.

slides.rishidean.com/roadmaps14
ANATOMY · EPIC

Epic: durable intent, with a fence

HOW TO DEFINE ONE
NAMEa real word, permanent, no numbers
GOALwhat’s true when it’s done
SCOPEwhat’s in
CUT LISTwhat’s deliberately out, in writing

The cut list is the agent-critical part: an agent can’t tell a gap from a decision unless the decision is written down.

## EPIC: BOOKING  (next: fully decomposed)
goal:  rider requests and completes a ride
scope: destination, estimate, match, lifecycle
cut:   scheduling, in-app payment, driver app
 
## EPIC: EXCEPTIONS  (later: directional)
goal:  the unhappy paths get handled
notes: cancellation, no-driver timeout…
// a fence: real, coming, not now

Specify the next epic fully; keep later epics directional. A future left unwritten is a future the agent builds early.

slides.rishidean.com/roadmaps15
ANATOMY · SPRINT

Sprint: slice it vertically, not horizontally

WEAK · HORIZONTAL LAYERS
S1  all the data models S2  all the APIs S3  all the UI

Nothing works until everything works. Nothing is verifiable until the end.

STRONG · VERTICAL SLICES
S1  the shell runs locally S2  a rider requests and gets matched S3  a full ride, start to finish

Each slice cuts the whole stack and ships a two-minute demo.

Demoable outcomes are how you verify agent work without reading every line. The demo is the verification interface.

Inside a sprint spec: eight fields

01 · OUTCOME

What demos when it’s done

02 · SCOPE

03 · BEHAVIOR

What the rider can do or observe

04 · RULES

Evidence returned, result written down

Read any field and ask what an agent would do if it were blank. That blank is a product decision you just delegated.

ANATOMY · FEATURE

Feature: a good spec makes the build trivial

VAGUE · A GUESS IN WAITING

“Rider can request a ride.”

A human asks questions. An agent invents the answers, and the build is a guess wearing your product’s name.

EXPLICIT · A MACHINE CAN CHECK IT
## FEATURE: ride request
✓ estimate shown before request is enabled
✓ matching runs as a staged sequence
✓ assignment shows driver + ETA
✓ mock data only; no network calls

Explicit criteria: the build is trivial, QA is decisive. Vague criteria: a product decision delegated to a code generator.

ANATOMY · THE BUG AND THE FIX

One token can’t do two jobs

THE BUG, IN ONE NUMBER
E5
“I am epic five” (identity: must never change) “I am fifth” (priority: changes weekly)

Commits, branches, and specs point at the token. Reorder once and they all point at the wrong thing.

THE FIX
BOOKING NEARBY

Names carry identity: real words, no numbers, permanent. The schedule alone carries order.

Sprint counters inside an epic (BOOKING-S2) are fine: they count creation order. And a dead epic gets a tombstone in the catalog, never a deletion, so history keeps resolving.

The name means the same thing forever, to a human skimming a commit log and to an agent resolving a reference.

ANATOMY · AUTHORSHIP

Contract above, cache below

CONTRACT
Roadmap Epic definitions
Humans own it
revised deliberately
CACHE
Sprint plans Generated detail

never hand-edited; regenerated

Wrong plan? Don’t fix it. Delete it, sharpen the contract, regenerate.

PMs: everything above the line is yours, and nothing below it should ever need your keyboard.
